- Снимок из текущего чата проекта (оригинальный файл находится в прикреплённых материалах беседы, но **не** в GitHub).

Точный URL галереи на скриншоте **не показан**. Не приписывать карточкам непроверенные исходные URL, case IDs или наличие полноразмерных файлов.
- Скриншот имеет размер **1559×849**; фотографии внутри карточек примерно **191–192×220–221 px**. Кропы пригодны только для внутреннего обзора, **не для итоговой hero/кейсовой галереи**.
- Коды заказов, имена пользователей, служебные/закрытые комментарии и ссылки на чужие аккаунты из старого интерфейса в новый не переносить.

## Shortlist для секции «Примеры проверок» [ГИПОТЕЗА, НЕ ПУБЛИКОВАТЬ]

1. **AMIRI · худи · «Оригинал»**: единственный визуально оригинальный кейс, необходим для сбалансированного показа формата. Нужны оригинальная основная фотография, разрешённые крупные детали и подтверждение, что этот verdict действительно выводился в законченной проверке.
2. **BALENCIAGA · чёрное худи · «Реплика»**: понятная категория streetwear и читаемый полный вид изделия; нужен файл оригинального фото + публично допустимая деталь.
3. **AIR JORDAN · бело-красные кроссовки · «Реплика»**: другая категория товара, расширяет ассортимент примеров; нужен оригинал фото и 1–2 изображения важных деталей.

**Резерв:** Moncler (пуховик) и Balenciaga (бирка) полезны как разные формы детального снимка после получения полноразмерных исходников и прав.

## Требуемые исходные материалы и metadata
Хранить только в **приватном** репозитории, после отбора и проверки прав:

`assets/checks/real/<case-slug>/cover.webp`; `detail-01.webp`; `detail-02.webp` (при наличии); отдельный `manifest.md` с: источник изображения, владельческие права / разрешение, дата получения, вердикт, разрешение на публичный показ статуса, указание опубликован ли кейс на старом сайте. Не прикреплять внутренние case IDs из снимка без необходимости.

Качество: желательно **≥1200 px по большей стороне** исходного изображения и резкость детали на экране; не растягивать скриншотную миниатюру ~190×220 px. Перед публикацией удалить EXIF, GPS, лица, личные данные и служебные сообщения. Тексты экспертных комментариев не публиковать (D-016). Если нет подтверждения выводов/прав, кейс остаётся внутренним иллюстративным контентом, без ярлыка «реальная проверка».

## Как продолжить без блокировки дизайна
- Сама секция уже спроектирована концептуально в `docs/STAGE_02_HOMEPAGE_SECTION_MAP_V1.md`: большая фотография, допустимый статус + детали, клик к обезличенному результату.
- Для следующей проверки композиции допустимы низкоразрешённые *внутренние* фото-кропы с пометкой «source screenshot / draft»; **не** заливать в публичный сайт и не выдавать за final assets.
- Не создавать генеративные поддельные проверки.
- Блокер для импорта оригинальных фото — **работоспособный точный адрес публичной галереи (URL со страницы на скриншоте) или экспорт оригиналов**; разрешения владельца проекта сообщено, файлов/доказательства условий пока нет.
- Архивирование выбранных изображений, их публикация и разработка desktop (этап 03) требуют отдельной проверки. Никаких изменений production.
