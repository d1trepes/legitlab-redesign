# LEGIT LAB — Build specification for Claude Code
**Версия:** 1.0, 08.11.2026  
**Тип:** обязательное ТЗ на **изолированную концептуальную демоверсию**. Не является подтверждением final UI или production-функций.

## 0. Контекст и приоритет
[ФАКТ] В репозитории нет файлов приложения (`package.json`, `src/`, `app/`) на момент передачи; есть полноценный архив документации, изображения и SVG. [РЕШЕНИЕ] Создать самостоятельное web demo без интеграции в действующий сайт. Исторический запрет разработки до закрытия этапа 02 отменён **лишь для обратимого прототипирования** решением D-030.

При конфликте: новое явное решение пользователя → `CLAUDE.md` / это ТЗ → последние D-xxx → старые документы. Дизайн не копировать с референсов дословно.

## 1. Продуктовое обещание и аудитория
LEGIT LAB — сервис оценки подлинности брендовых вещей по присланным фотографиям: одежда, обувь, сумки и аксессуары. B2C, Беларусь; русский UI. Позиционирование — помочь человеку принять более обоснованное решение о вещи до/после покупки, не гарантировать подлинность. Главная проблема существующего UX: неясно, что пользователь получит, сколько стоит проверка, как начать, много мелких системных надписей, превью результата недостаточно понятно. Источник: `docs/UX_AUDIT.md`. Около 300 бесплатных обращений — **непроверенная цифра**, не публиковать.

## 2. Визуальный язык (подробно)
- **Editorial fashion × streetwear × authentication**: ощущение качественного fashion-журнала и точной экспертной оценки, а не банковского кабинета, криптоплатформы, интернет-магазина или sci-fi AI.
- Ритм: впечатляющий первый экран, далее крупные аккуратно выстроенные предметные/контентные секции, затем утилитарные понятные шаги. Много визуального воздуха **только там, где он помогает иерархии**, не пустые гигантские секции ради длины.
- Цвет: light default — молочно-белая/светло-серая основа, near-black текст, серые разделители; dark через настройки — угольная/почти чёрная основа, светлый текст. Без хроматического акцента. Состояния статусов, если появятся, обозначать словами/иконкой, а не одним цветом.
- Typography: выразительный display для бренда/главных секций, спокойный читаемый UI/body, кириллица, разумная ширина строк. Пара-кандидат **TT Firs Neue / TT Commons Pro** только при наличии легальных файлов. Временный fallback — системные шрифты; явно отметить ограничение. Не предлагать отвергнутые Inter/Manrope/Onest/Unbounded как брендовый выбор.
- Grid: максимальная ширина контента ориентировочно 1280–1360 px; осмысленные боковые поля; на 1440 верхнее меню не тесное; на 390 не плодить микрошрифт. Это **технические рабочие параметры демо**, не окончательно утверждённые токены. Используй CSS custom properties для цветов, отступов, типографики и радиусов, чтобы быстро скорректировать после просмотра.
- Фотостиль: один сильный честный предметный hero из пользовательских файлов, без случайных fashion-stock фотографий, бессмысленных кроссовок и fake-case-галерей.
- Motion: короткое, неброское появление hero и плавные UI-переходы, не допускать тяжёлых 3D/видео ради эффекта, обязательный prefers-reduced-motion. Статичный кадр должен быть выразительным.
- Элементы: сдержанная геометрия, рамки и разделительные линии, небольшие радиусы кнопок, интуитивная плотность текста; никаких капсул вокруг каждого подзаголовка, сеток из одинаковых карточек, кислотного свечения, декоративных «data dots».
- Logo: SVG C2 Compact (exact polygon) + набранный `LEGIT LAB`; не замещать фирменный знак декоративным H1.

## 3. Desktop 1440: все 8 блоков
**01 Header.** Framed navbar как композиционный объект. Слева выбранный знак C2 + текст LEGIT LAB. В центре релевантные ссылки: «Стоимость», «Кошелёк», «Статьи». Справа Telegram/TikTok, «Войти», настройки (тема внутри панели), сильная кнопка «Начать проверку». Если не помещается — оптимизировать межэлементный ритм, не переходить в hamburger на desktop. Для неготовых кабинета/авторизации показать демо-пустое состояние, не выдавать за настоящий вход. Не придумывать ссылки Telegram/TikTok: проверить подтверждённые URL в материалах либо сделать недоступным с объяснением.

**02 Hero.** Крупнейшая декоративная надпись `LEGIT LAB` позади контрастного худи, перед буквами, с читаемой геометрией обеих тем. Light → `assets/hero/hero-hoodie-black-light.webp`; Dark → `assets/hero/hero-hoodie-white-dark.webp`. Использовать `object-fit:contain`, не обрезать капюшон/рукава/бирки, кроме предусмотренного нижнего края предплечья. **НЕ** выкладывать текст в фоторастр, **НЕ** делать брендовую надпись семантическим H1. В нижнем левом поле:
H1 **«Проверка подлинности брендовых вещей»**
P **«Помогаем понять, стоит ли покупать вещь и что именно ты держишь в руках.»**
CTA **«Начать проверку»** → `/check`
Secondary **«Как это работает»** → `#how-it-works`.
Типографика должна выдерживать изображение и быть доступной на узком экране. Изображение не должно перекрывать полезный текст или кнопку.

**03 Примеры проверок.** Поверхность со скруглёнными верхними углами плавно перекрывает нижнюю часть hero; композиционная идея из Athlete Showcase без копирования. Поскольку в репозитории **нет публичных разрешённых реальных case photos и заключений**, НЕ изобретать «реальные проверки» и не показывать якобы найденный результат. Вместо этого — выразительная секция «Примеры проверок» с **явно обозначенным макетом структуры результата** (нейтральный образец: тип вещи / полученные фотографии / наблюдения / статус / итог, без вымышленного вердикта и текста эксперта). Текст «Демонстрационный пример. Не является результатом реальной проверки». Кнопка «Посмотреть пример результата» → `/example-result`. Оставить в структуре место для будущих подтверждённых кейсов и описать в implementation notes. Не публиковать конфиденциальные комментарии.

**04 Как мы проверяем.** Содержательный рассказ на русском в двух различимых перспективах: маршрут клиента (выбрать тип вещи → приложить качественные фото → получить оценку после обработки при доступном сервисе) и общий смысл экспертной работы (специалист изучает видимые особенности на фото; оценка по фото имеет ограничения). Точные методы, количество экспертов, очереди/сроки — только при документальном подтверждении; можно честно обозначить, что детализация процесса уточняется. Не приписывать компьютерному зрению / AI / гарантированной проверке.

**05 Стоимость.** Сдержанный контрастный pricing-артефакт с понятным местом для цены **одной проверки**, валюта default **BYN**. Реальная цифра и модель списания не подтверждены: писать «Точная стоимость уточняется перед оформлением» или «Стоимость будет указана до подтверждения заявки (демо)», без цифр и фальшивой кнопки «Оплатить». Демо-CTA → `/check`. Если country control есть — default Беларусь, Россия не изображается работающим способом оплаты. Избегать внутреннего CRD/Tokens как основной цены.

**06 Статьи.** Editorial типографическая сетка/список из 2–3 **помеченных тем для будущих статей**, если нет утверждённых публикаций с доступным контентом. Например «Какие фотографии помогут при оценке вещи», «Почему один снимок не всегда достаточен», «Как читать заключение эксперта» — как темы, **не** как существующие материалы или фактические кейсы. Можно написать полноценные оригинальные статьи и открыть `/articles`; не приписывать их текущему сайту без проверки. Каждая страница с читабельным текстом и CTA.

**07 Финальный CTA.** Простая крупная заключительная композиция с повтором понятной ценности услуги и «Начать проверку» → `/check`. Не копировать hero второй раз.

**08 Footer.** Logo+wordmark, навигация, честный контекст demo и ссылки на реально проверенные каналы/документы (если известны). Не изобретать телефон, адрес, почту, реквизиты, юридические гарантии, политику и соглашение.

## 4. Mobile 390 / промежуточные ширины
- Header → компактная доступная навигация: допустимо мобильное меню с aria-controls/expanded и нормальным фокусом; на desktop — без hamburger.
- Декоративный бренд и худи сохраняют узнаваемую силуэтную глубину, но **главное — H1 и кнопки**. Можно изменить порядок и размер арт-слоёв без изменения исходной фотографии.
- Не допускаются обрезанные CTA, horizontal scroll, нечитаемый 12px body, недоступные кнопки/меню, фактически белая картинка на белом.
- Секция примеров должна читаться сверху вниз и визуально отличаться от hero.
- Тёмная тема содержит реальные dark-ассеты, не filter:invert.
- Проверить 390, 768, 1024, 1440 и на масштабировании 200%.

## 5. Веб-сценарий заявки (demo, а не сервер)
Маршрут: `/` → «Начать проверку» → `/check` → выбор категории → бренд (поле/список как демо) → загрузка 1+ локальных изображений с валидацией типа/размера и preview → summary → **«Это демонстрация: заявка не отправлена, платежей и экспертизы нет»**. Не сохранять реальные фото в облако, не вызывать сторонний AI, не обещать заключение после нажатия. Кнопка на финальном шаге может вернуться на главную или сбросить демо. Ошибки формы, клавиатура и отзывчивость обязаны работать. Не показывать фальшивые transaction IDs/статусы в обработке.

Маршрут `/example-result`: **пример структуры, а не реальный кейс**. Объяснить, какие поля может содержать заключение, с нейтральными заглушками, без ложного «Оригинал/Реплика», фото клиента, придуманного автора или обещанного QR-сертификата.

`/articles`: список и материалы если созданы. `/wallet`, `/login`: либо честный демо-экран «недоступно в концептуальной версии», либо нефункциональная навигация **не маскируется** под настоящий продукт; предпочтительно экран, чтобы не было broken links. Открытие Telegram Mini App из браузера не симулировать.

## 6. Технология
Стартовать с **Next.js App Router, TypeScript**; семантическая разметка; CSS Modules или Tailwind на выбор, но не смешивать без нужды. Копировать **производные** ассеты из `assets/` в `public/` при сборке или хранить ясную ссылку на канонические; оригинальные файлы в `assets/` не модифицировать. Компонентная структура: Header, ThemeSettings, Hero, Examples, Process, Pricing, EditorialArticles, FinalCTA, Footer; страницы check / example-result / articles / login / wallet как применимо. Предпочтителен минимальный надёжный стек без анимационных монстров и сторонних CDN.

CSS variables: background, surface, text, muted, border, accent-neutral, spacing, max-width, radius, display type scale; `data-theme` для light/dark, переключение доступно из настроек. Сохранение темы в localStorage по возможности, без гидратационных сбоев; системная тема не должна самовольно отменять default light без явного выбора.

SEO: title/description на русском, правильный H1, навигация, ссылки, Open Graph только если есть подходящий разрешённый арт; закрыть от индексации, если это staging без одобрения. Доступность: контраст, alt только для смысловых изображений, семантический outline, focus-visible, управление клавиатурой, reduced-motion.

## 7. Что НЕ входит и что предоставить на выходе
Нет продакшн-интеграции, логина, кошелька, платежей, объединения аккаунтов, Telegram Mini App, контентного CMS, юридической экспертизы. Не выдавать это за готовое.

Результат = работающий сайт-демо + команда запуска + проходящие доступные lint/typecheck/build + минимум две темы + путь /check + честный /example-result + desktop/mobile скриншоты при наличии инструмента + краткий отчёт, в том числе о недостающих лицензиях/публичных кейсах/тарифах.

Окончательное принятие визуала — за инициатором, даже если сборка технически готова.
