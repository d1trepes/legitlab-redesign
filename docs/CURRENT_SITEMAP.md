# Legit Lab — текущая карта интерфейсов (draft, этап 01)

**Дата:** 07.11.2026  
**Статус:** предварительная реконструкция по скриншотам пользователя; не подтверждена кодом, аналитикой или полным функциональным тестом.  
**Платформы:** публичный сайт / веб-интерфейс `legit-lab.com`, Telegram-бот, Telegram Mini App, Telegram-канал.  
**Важно:** сайт не является только лендингом: на нём есть личные разделы и создание заявки. Mini App не следует считать просто мобильной версией без проверки авторизации и платформенных различий.

## A. Сайт `legit-lab.com` — видимые разделы

```text
legit-lab.com
├── Home
│   ├── Популярные бренды / цены в CRD
│   ├── Экспертные материалы (минимум 3 статьи по контексту пользователя)
│   │   └── Страница статьи: пример Moncler Puffer Legitcheck
│   └── Глобальная история проверок
│       └── Публичный отчёт: бренд, вердикт, время, фотографии
├── New Request (создание проверки)
│   ├── Шаг 01/04: выбор бренда, поиск, популярные бренды, длинный список
│   ├── Шаг 02/04: выбор категории
│   ├── Шаг 03/04: фотографии по инструкции + дополнительные фото + комментарий
│   └── Шаг 04/04: НЕ ПОКАЗАН (логика неизвестна)
├── Wallet
│   ├── Баланс (CRD), история транзакций
│   └── Пополнение
│       ├── Пакеты 50 / 150 / 300 / 1000 Tokens и цены в USD
│       ├── Telegram Stars (на сайте отображён переход в Mini App)
│       ├── Crypto (визуально представлен)
│       └── Bank Card (помечен SOON)
├── Orders
│   └── Пустое состояние, CTA «Создать заявку»
└── Profile
    ├── Статус учётной записи, счётчики
    ├── Привязки Telegram / email
    ├── Данные пользователя
    ├── Оплата и пополнение, сертификаты
    ├── Безопасность, политика возврата
```

Не подтверждено: все URL, результат перехода по CTA, доступ без авторизации, поведение поиска/форм, успешная оплата, сохранение заявки, этап 04, состояние заказа после оплаты и реальное содержимое сертификата.

## B. Telegram — видимые точки входа

```text
Telegram-канал Legit Lab
├── Закреплённое приветствие / позиционирование
├── Посты о причине запуска сервиса
├── Обучающий контент / сравнения
├── Публичный кейс с описанием признаков
└── Упоминание и ссылка на @legit_lab_bot

Telegram-бот @legit_lab_bot
├── Описание возможностей и категорий
├── /start
├── Персонализированное приветствие
├── Ссылка на Telegram-канал
└── CTA «Открыть приложение»
    └── Telegram Mini App
        ├── Home — бренды, статьи, история проверок
        │   └── Публичный отчёт с фотографиями
        ├── Wallet — баланс, пополнение, пакеты Tokens
        ├── New Request — те же 4 этапа (показаны 01 и 03; 02 есть в desktop)
        ├── Orders — пустое состояние
        └── Profile — авторизация через Telegram, детали и сервисные разделы
```

**Наблюдаемое различие:** в примере профиля desktop Telegram не привязан, email привязан; в Mini App Telegram указан как подключённый, email не привязан. Это разные видимые состояния, но **не доказательство** того, что балансы и заказы разделены.

## C. Восстановленные пользовательские сценарии

1. **Через Telegram:** канал или прямое открытие бота → `/start` → «Открыть приложение» → Mini App Home → New Request → бренд → категория → фото → **дальнейшая часть не проверена**.
2. **Через сайт:** landing/Home → New Request → бренд → категория → фото → **дальнейшая часть не проверена**.
3. **Контентная точка входа:** статья либо история → знакомство с информацией/отчётом → **переход к заказу по реальному CTA не проверен**.
4. **Пополнение:** Wallet → пакеты Tokens → Stars или Crypto → **фактическая платёжная операция не проверена**.
5. **После заказа:** Orders → результат/сертификат — **публичные отчёты существуют, но личная цепочка заказа и выдачи результата не проверена**.

## D. Открытые вопросы для подтверждения
