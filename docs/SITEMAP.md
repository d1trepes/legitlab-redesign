# LEGIT LAB — карта продукта

Статический экспорт Next.js, `trailingSlash`, всё работает под `/legitlab-redesign/` и переживает обновление страницы.

## Публичная часть

| Маршрут | Что это |
|---|---|
| `/` | Главная: первый экран с 3D-кольцом → что проверяем → примеры проверок → как проверяем (интерактивный разбор) → итоги → бренды и цены → статьи → финальный призыв |
| `/catalog/` | Каталог 18 настоящих проверок: поиск, фильтры (категория, бренд, итог), сортировка, пустое состояние. Состояние фильтров хранится в адресе |
| `/catalog/[id]/` | Публичный отчёт: бренд, категория, итог, фото. Заключение и сертификат закрыты — их видит только владелец |
| `/how-it-works/` | Шаги, что смотрит эксперт, какие фото нужны по категориям, как снимать, ограничения оценки по фото, FAQ |
| `/pricing/` | Цена по брендам, что такое кредиты, пакеты в BYN (демо-курс), срочность, калькулятор «на сколько проверок хватит» |
| `/articles/`, `/articles/[slug]/` | Материалы с кратким собственным текстом и ссылкой на оригинал |
| `/security/` | Как защищены аккаунт и фото: двухфакторная защита, удаление метаданных, что видно публично |
| `/verify/?id=` | Проверка сертификата по QR |
| `/brand/` | Доработка логотипа рядом с оригиналом |
| `/login/`, `/register/`, `/forgot/` | Вход (пароль → код), регистрация, восстановление, вход через Telegram (демо) |

## Кабинет (нужен вход)

| Маршрут | Что это |
|---|---|
| `/new/` | Мастер: вещь → фото → условия → подтверждение → готово. Черновик хранится, поэтому уход в кошелёк и возврат ничего не теряет |
| `/orders/` | Заявки с фильтром по статусу |
| `/orders/view/?id=` | Заявка: таймлайн, фото, итог, пример заключения, досъёмка, пример сертификата с QR, демо-панель эксперта |
| `/wallet/` | Баланс, на сколько проверок хватит, пакеты, демо-оплата, история операций |
| `/profile/` | Данные, безопасность (пароль, двухфакторная защита, сеансы, журнал входов), Telegram, тема, уведомления, сброс демо, выход |

`/orders/[id]` из брифа заменён на `/orders/view/?id=`: заявки создаются в браузере, а статический хостинг не может отдать страницу по адресу, которого не было на момент сборки.

## Главный путь

1. Первый экран → «Начать проверку» (или карточка категории — тогда категория уже выбрана).
2. Нет входа → `/login/?next=/new/`, после входа возврат в мастер.
3. Мастер: вещь → фото по слотам → срочность и промокод → подтверждение.
4. Не хватает кредитов → `/wallet/?return=new` → пакет → демо-оплата → возврат на шаг подтверждения с теми же данными.
5. Заявка создана → `/orders/view/` → статусы → (досъёмка) → итог → сертификат.

## Слой данных

`lib/store.ts` — единственная точка доступа к данным (пользователи, сеанс, заявки, операции, черновик) поверх `localStorage`; фото лежат в IndexedDB (`lib/photos.ts`). Интерфейс знает только функции слоя, поэтому замена на API не трогает экраны.
