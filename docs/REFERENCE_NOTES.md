Референсы предоставлены пользователем в виде скриншотов; сами изображения ещё нужно поместить в `references/`. До этого Codex не должен угадывать композиции.

## Предварительная гипотеза темы (07.11.2026)
- Инициатору нравится **тёмный интерфейс LegitApp**; предложил исследовать тёмную тему как основную и светлую как опциональную.
- **ЭТО НЕ УТВЕРЖДЁННЫЙ ВИЗУАЛ**: прежняя гипотеза светлой editorial-подачи остаётся кандидатом. В этапе 02 сравнить обе на одинаковых сценариях (главная, кейсы, статья, заявка, оплата), включая 1440/390, контраст, вёрстку фото и состояния.
- Двойная тема добавляет второй набор визуальных состояний, тестирования и поддержки — не считать переключатель «бесплатным бонусом».
- Не переходить в Codex и не рисовать готовый дизайн до выбора направления.

## Метод изучения
Для каждой секции записать: конкретный референс → визуальный приём → задача для пользователя → как адаптировать на 390 px → чего избегать.

## Критерии
- Настоящие вещи и фотографии деталей; фото пользователей только с разрешения, без лишних персональных данных.
- Читаемость, контраст, сетка и явный CTA важнее декора.
- Не подделывать реальные экспертные заключения, отзывы и доказательства.
- Для logo A/B/C сохранять SVG отдельно; primary выбирается только после согласования.

## Ещё нужно решить
- Шрифты, размеры, веса, сетка.
- Выбор фотостиля и доступных ассетов.
- Логотип: концепции, small-size тесты, wordmark.
- Motion и reduced-motion.
