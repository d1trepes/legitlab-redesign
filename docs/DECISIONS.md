# DECISIONS — журнал согласованных решений
Обновлено: 2026-11-07.

## [РЕШЕНИЕ]
- D-001: Название Legit Lab и домен legit-lab.com сохраняем.
- D-002: На первом этапе только B2C; B2B и партнёрские программы исключены.
- D-003: Без Figma; ChatGPT = штаб, Codex = работа в коде, GitHub = общие спецификации и контроль версий.
- D-004: Сначала полный UX-аудит, затем референсы и айдентика, только потом разработка.
- D-005: Главная: header → hero → real checks → how we check → pricing → SEO/articles → final CTA → footer.
- D-006: Пользователь лично утверждает выбранную айдентику, логотип и направление дизайна; сохраняем альтернативы.
- D-007: Этот репозиторий только для отдельной демоверсии; действующий сайт не изменяем.

- D-008 (07.11.2026, инициатор): **Принцип локализации стоимости для B2C** — пользователь должен иметь возможность выбрать свою страну и увидеть понятную цену в соответствующей валюте. Для Беларуси — BYN; для будущего выхода в Россию — RUB; для прочих стран — валюта только если этот рынок и способ оплаты реально поддерживаются. Причина: USD/CRD/Tokens на текущих экранах создают непонимание конечной стоимости. Влияние: UX цены, оформления, кошелька и платёжного сценария. **Не утверждает** автоматическое определение страны, точное место селектора, платёжного провайдера или готовность международных платежей.


- D-009 (07.11.2026, утверждено инициатором): **При первом входе страна по умолчанию — Беларусь; валюта интерфейса цен — BYN.** Обязательного экрана выбора страны перед знакомством с услугой не будет. Пользователь может явно сменить страну. Россия/RUB — только на будущем этапе выхода на рынок, не включать её как доступный способ оплаты без подтверждённой поддержки. Для любых других стран действуют те же ограничения. Размещение селектора и техническая реализация пока не утверждены.
- D-010 (07.11.2026, требование инициатора к отображению): Для Беларуси использовать **новый официальный графический знак белорусского рубля** (кириллическая «Б» с горизонтальной чертой), утверждённый постановлением Правления Нацбанка № 25 от 27.01.2026, действует с 04.02.2026. Текстовый международный код валюты — **BYN**, для России — **RUB** (знак ₽). Не заменять официальный знак нарисованной на глаз буквой «Б», латинской B или прежним Br: перед внедрением получить утверждённый оригинал/вектор и проверить корректность воспроизведения, права и техническую доступность. Пока символ недоступен — выводить BYN текстом; не выдавать суррогат за официальный знак. Источники: https://prg.kz/Document/?doc_id=32830894 и https://www.rrb.by/news/graficeskii-znak-oficialnoi-deneznoi-edinicy-respubliki-belarus-20260311-1304.

- D-011 (07.11.2026, инициатор): **Русский — основной язык пользовательского интерфейса на первом этапе** (Беларусь и дальнейшая работа на рынках СНГ). Все названия разделов, кнопок, описание услуги и сообщения посетителям пишем по-русски. Внутренние имена файлов и компонентов могут оставаться на английском. Англоязычная версия — [ГИПОТЕЗА] далёкого расширения на другие рынки, без сроков и без текущей задачи реализации.
- D-012 (07.11.2026, инициатор): **Самостоятельные маршруты заявки**: с `legit-lab.com` CTA «Проверить вещь» ведёт к оформлению **на сайте**, а из Telegram-бота открывается Mini App и заявка оформляется **там же**, без обязательного перехода между платформами. При этом общие сервер/заказы/баланс — [УТОЧНИТЬ], не утверждены и не исключены.
- D-013 (07.11.2026, инициатор): Название смыслового блока главной — **«Как мы проверяем»** (русское пользовательское название для ранее записанного `How We Check`). Секция раскрывает **что делает эксперт после получения фотографий, по каким признакам оценивает вещь и как формирует вывод**; параллельно понятен клиентский процесс, но реальные экспертные шаги, сроки и ограничения запрашиваются у команды, а не выдумываются. Конкретный макет блока ещё не утверждён.

- D-014 (07.11.2026, уточнение инициатора): Присланные заключение, служебный экран и сертификат — **разные иллюстративные примеры**, а VLONE-сертификат — шаблон. **Не фиксировать несоответствие изображения сертификату, отсутствие связей между разными скриншотами или необходимость их расследовать как найденный дефект продукта.** Реальное объединение конкретных фото/вывода в одном заказе по этим материалам не тестировалось. Уточнение отменяет ошибочные подозрения в предыдущем черновике аудита, без заявления о проверке всей системы сертификатов.
- D-015 (07.11.2026, подтверждено инициатором): Приоритетными UX-пунктами результата остаются **мелкая, сложная техническая типографика** и **отсутствие ясного примера того, что клиент получит после оплаты**. В рамках IA рассмотреть демонстрацию структуры заключения до оплаты; конкретный вариант и материалы ещё не утверждены.

- D-016 (07.11.2026, ответ представителя команды, передан инициатором): **Комментарии пользователей и экспертов не выводятся публично по соображениям конфиденциальности.** Для редизайна считать это ограничением раскрытия: не публиковать настоящие комментарии, даже короткие фрагменты, без отдельного явного разрешения и проверки прав. Это **не запрет показывать их самому владельцу заказа** после авторизации.

## [ГИПОТЕЗА] — ЕЩЁ НЕ УТВЕРЖДЕНО
- H-001: Основная визуальная тема светлая, почти монохромная, fashion-editorial / streetwear.
- H-002: Основная аудитория Беларуси — покупатели брендовой одежды на ресейле.
- H-003: Процент участника по product/design/growth: переговорная позиция 15–20%, база/срок/обязанности ещё не согласованы.
- H-004: Платные продажи возможны после проверки цены, законных платежей и воронки; не гарантированы.

- H-005: Непроверенная UX-деталь — лучше ли показывать селектор страны рядом с ценой, в профиле или на шаге оформления; автоматическая геолокация по IP, курсы конвертации, валюта фактического списания и доступность методов оплаты не утверждены.


- H-006 (07.11.2026): **Тёмная основная тема + опциональная светлая** — новая визуальная гипотеза инициатора после изучения LegitApp. Ранее зафиксированная светлая editorial-гипотеза **не отменена и не утверждена как финальная**. В этапе 02 сравнить тёмную и светлую подачи на одинаковых сценариях с проверкой контраста, фото, чтения статей, mobile и стоимости поддержки двух тем. Тема-переключатель **не утверждён в объёме разработки**.
- H-007 (07.11.2026): Доверие обеспечивать проверяемым описанием услуги, ответственностью эксперта, понятными заключениями, честными ограничениями и обезличенными реальными кейсами; детали закрытой методики не раскрывать. Точный объём публичного объяснения определить после беседы со специалистом, без выдуманных квалификаций/чисел.
- H-008 (обновлено 07.11.2026): В блоке «Примеры проверок» показывать **демонстрационную структуру результата**, без реальных комментариев пользователей/экспертов, их фрагментов, личных идентификаторов и чужих фото без прав. Возможны видимые названия разделов, нейтральная заглушка «Заключение доступно владельцу проверки», общий формат сертификата и **только разрешённые к публичному показу** вердикты/фото. Демонстрационный пример явно маркировать, не выдавать за реальный кейс. **CSS blur не обеспечивает конфиденциальность**, секретный текст не загружать в DOM/HTML. Конкретный контент и место блока ещё не утверждены.

## Этап 02 — уточнения инициатора 08.11.2026

**[РЕШЕНИЕ] D-017.** Цветовое направление: монохром (белый, чёрный, серые оттенки) без хроматического акцента; **светлая тема по умолчанию**, полноценная тёмная через «Настройки». Ранее записанная H-006 о тёмной теме по умолчанию **устарела**. Это не утверждение конечных HEX и UI-экранов.

**[РЕШЕНИЕ] D-018.** Основа hero: огромный композиционный текст **LEGIT LAB** (не H1); перед ним рука с **худи и видимыми свисающими бирками** по принципу Bounce; смысловой текст снизу слева: H1 **«Проверка подлинности брендовых вещей»**, описание **«Помогаем понять, стоит ли покупать вещь и что именно ты держишь в руках.»**, CTA **«Начать проверку»** / **«Как это работает»**. Не делать hero магазином одежды и не заменять главный текст на «Проверь вещь». Финальный ассет и движение пока не утверждены.

**[РЕШЕНИЕ] D-019.** Desktop-навигацию исследовать в формате **framed navbar**, с полным меню и без hamburger на desktop. Требуемые функции/пункты: wordmark Legit Lab, «Стоимость», «Кошелёк», «Статьи», Telegram, TikTok, «Войти», настройки и основной CTA. Тема в настройках, не отдельной кнопкой в navbar. Раскладка и доступность «Кошелька» до входа — [УТОЧНИТЬ].

**[РЕШЕНИЕ] D-020.** Композиционный приём: следующая согласованная секция «Примеры проверок» перекрывает нижнюю часть hero поверхностью со скруглёнными верхними углами (анализ Athlete Showcase, не копия). Окончательные размеры и мобильная версия — [УТОЧНИТЬ].

**[РЕШЕНИЕ О КАНДИДАТЕ] D-021.** Шрифтовое направление для проверки: **TT Firs Neue + TT Commons Pro** с русской кириллицей. Нужна проверка актуальных коммерческих лицензий, реальных шрифтовых файлов и читабельности до выпуска. **Onest и Unbounded отклонены инициатором**, не возвращать в активный shortlist; Inter/Manrope также не предлагать как основной стиль.

**[РЕШЕНИЕ О ПРОЦЕССЕ] D-022.** Направление hero и пользовательские предпочтения можно документировать; **этап 02 не закрыт**, пока не выбраны и не проверены hero-ассет, две темы, точная визуальная система и **2–3 варианта логотипа**. Не начинать код через Codex до отдельного разрешения.

**[ГИПОТЕЗА]** Преимущественно прямоугольные кнопки с небольшим радиусом; простое одноразовое 2.5D-появление руки и худи; техника видео/3D — альтернатива после оценки теста. Точные параметры не утверждены.

Подробное объяснение: [STAGE_02_ART_DIRECTION.md](STAGE_02_ART_DIRECTION.md).


**[РЕШЕНИЕ] D-023 (08.11.2026, инициатор).** Требование к исходному hero-изображению: **предплечье поднимается из нижнего центра и является единственной частью, выходящей за границу кадра**. Худи целиком (капюшон, обе манжеты, рукава, корпус, нижний край, бирки) остаётся внутри кадра, кисть целиком видима. Никаких ссылок на первое сгенерированное изображение при новой генерации: композицию строим с нуля. Этот пункт уточняет D-018, но не утверждает готовый ассет. См. `STAGE_02_GENERATION_KIT.md`.


**[РЕШЕНИЕ] D-024 (08.11.2026, инициатор).** Парные объекты hero для цветовых тем: **в светлой теме — чёрное/графитовое худи**, **в тёмной — белое/светлое худи**. Светлая тема остаётся default. Одинаковые силуэт, рука снизу, положение бирок и кадрирование; отличия только в материале/цвете худи и необходимой светотени. Чёрный присланный вариант — текущий предпочтительный кандидат, белая версия пока не создана/не утверждена; итоговый hero ещё нужно проверить в контексте сайта. Не применять CSS invert к руке. См. `STAGE_02_ART_DIRECTION.md`, `STAGE_02_GENERATION_KIT.md`.


**[РЕШЕНИЕ] D-025 (08.11.2026, инициатор).** Оба ранее сгенерированных ассета худи **не принимаются как финальные**: в них предплечье визуально проходит сквозь ткань/горловину худи. Сохраняется предпочтение объёмной ткани, реалистичных складок и бирок, а также black-on-light / white-on-dark (D-024). **Новая физическая геометрия хвата:** рука поднимается снизу строго **перед одеждой**, пальцы сжимают наружную складку у верхнего плечевого шва возле воротника, худи свисает **позади** руки, предплечье не находится в рукаве, капюшоне, кармане или корпусе. Все детали худи в кадре, только нижнее предплечье может пересекать нижнюю границу. Два независимых V4-промпта см. `HERO_ASSETS_V4.md`. **Этап 02 и итоговый визуал всё ещё не закрыты.**


**[РЕШЕНИЕ] D-026 (08.11.2026, инициатор).** Текущие чёрный и белый варианты худи **сохраняем как рабочие hero-ассеты**, несмотря на возможные будущие правки анатомии руки. Две темы: black/light, white/dark (согласно D-024). Подготовлены RGBA PNG и WebP в `assets/hero/`, белый фон вырезан без изменения рисунка предмета; см. `HERO_ASSET_MANIFEST.md`. **Не считать утверждением финального UI или завершением этапа 02**. Повторно генерировать только по отдельному запросу.


**[РЕШЕНИЕ] D-027 (08.11.2026, инициатор).** Предыдущие сгенерированные hero-ассеты исключены из выбранного направления. Единственный источник для двух hero-изображений — переданный пользователем оригинальный RGBA PNG с чёрным и белым худи. Нужен только точный разрез по вертикали, без генерации, ретуши, дорисовки, изменения позы, ткани, бирок и руки. Имена канонических файлов: `assets/hero/black-hoodie-hand.png` (светлая тема), `assets/hero/white-hoodie-hand.png` (тёмная тема); сохранить совместимость с существующими путями `hero-hoodie-black-light.*` / `hero-hoodie-white-dark.*`, но заменить их содержимое на указанный пользовательский источник. **Статус доставки двоичных файлов: ОТКРЫТО, не выдавать документацию за завершённую замену в GitHub.**

**[НАПРАВЛЕНИЕ ДЛЯ ИССЛЕДОВАНИЯ, НЕ ФИНАЛЬНОЕ УТВЕРЖДЕНИЕ] L-001 (08.11.2026).** Среди трёх показанных вариантов A/B/C инициатор предпочёл **C** — самостоятельный наклонный геометрический знак из двух элементов. Развивать пропорции, негативное пространство и чтение в favicon, без LL-монограммы, scanning/LegitApp мотивов. Варианты A/B сохранить как архив; окончательный логотип не выбран, Codex не запускать.
