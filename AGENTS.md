# AGENTS.md — правила для Codex

## Роль и контекст
Работаем над отдельной демоверсией Legit Lab (Беларусь): B2C-сервис проверки оригинальности одежды, обуви и аксессуаров по фото. Название **Legit Lab** и адрес **legit-lab.com** не меняем. Никаких изменений в действующем production без разрешения.

## Источники истины
Перед задачей прочитай `docs/PROJECT_BRIEF.md`, `docs/ROADMAP.md`, `docs/DECISIONS.md`, `docs/REFERENCE_NOTES.md` и **`docs/STAGE_02_ART_DIRECTION.md`**. Если задания противоречат решениям, сообщи и запроси уточнение. Разговоры ChatGPT Project не считаются автоматически доступными Codex.

## Материалы текущего UX-аудита
Прежде чем менять IA или проектировать интерфейс, прочитай `docs/UX_AUDIT.md` и `docs/CURRENT_SITEMAP.md`. Это **рабочие наблюдения по скриншотам**, не окончательные решения и не описание проверенной функциональности. Никаких задач на код до отдельного утверждения пользователя. Не добавляй личные данные и публичные кейсы без подтверждения прав.

## Дополнение к источникам этапа 01
Читай также `docs/EXPERT_WORKFLOW_NOTES.md`. Сведения о производственном приложении основаны на предоставленном README и требуют проверки в исходниках; слова специалиста о трёх помощниках не являются подтверждением нескольких экспертов для каждого заказа.
В `docs/REFERENCE_NOTES.md` добавлен LegitApp — только для анализа UX и композиции. **Светлая тема по умолчанию, тёмная через настройки** — принятое предпочтение этапа 02 (см. `docs/STAGE_02_ART_DIRECTION.md`, `docs/DECISIONS.md`). Дизайн-токены и сам переключатель не реализовывать до финального утверждения.
Не показывать внутренние базы и закрытую методику, но не заменять объяснение экспертного вывода произвольной галереей.

## Обязательный процесс
1. Сначала UX-аудит и карта экранов/воронок.
2. Потом анализ конкретных референсов, типографики, сетки, фотостиля и 2–3 вариантов логотипа.
3. Пользователь выбирает и утверждает визуальное направление.
4. Только после этого кодируем **всю desktop-главную**.
5. Далее mobile, Telegram entry, web app, состояния заказа.
6. Позже — система соцсетей, маркетинговые материалы.

**Не рисовать случайный интерфейс при отсутствии утверждённых референсов.** Уточняй конкретные визуальные приёмы и назначение блоков. Не копируй чужой дизайн и медиа без прав.

## Стиль (пока ГИПОТЕЗА)
Light editorial fashion × streetwear × authentication; почти монохром, читаемая типографика, настоящие фотографии деталей вещей. Нет бирюзовому cyber-glow, случайным точкам, бессмысленным надзаголовкам, декоративным AI-эффектам, придуманным бейджам доверия. Визуальное решение окончательно утверждает пользователь.

## Язык и UX-маршруты (утверждено в этапе 01)
- Пользовательские заголовки, навигация, кнопки и интерфейсные тексты — **на русском**, без англоязычного UI на первом этапе. Английская версия — лишь возможная фича дальнего расширения, не задача для Codex.
- На `legit-lab.com` «Проверить вещь» запускает оформление **в браузере**; внутри Telegram-бот → Mini App, оформление **в Mini App**. Не вводить обязательный перевод между платформами.
- Секция `How We Check` называется для пользователя **«Как мы проверяем»**. Объяснять только подтверждённую командой работу эксперта и ограничения оценки по фотографиям.
- Перед IA-задачами читать `docs/PROPOSED_SITEMAP.md`, но это **черновик**, не разрешение на код или визуал.

## Главная: обязательные секции
Header → Hero → Реальные проверки → Как проверяем → Цена → SEO-статьи → Final CTA → Footer.

## Требования к реализации
- Desktop 1440 и mobile 390; проверять читаемость, контраст, фокус, отсутствие горизонтального скролла.
- Все интерактивные CTA должны вести в понятные сценарии. Если сценарий не реализован, обозначить демо-состояние.
- Все альтернативы логотипов сохранять отдельно, не перезаписывать до утверждения.
- Не выдумывать реальные результаты проверок, реальные отзывы, продажи или гарантии 100% оригинальности.
- Не подключать платёжные системы к настоящим деньгам в демо.
- Короткие понятные коммиты или PR, отчёт о сделанном и нерешённых вопросах.
- Figma в процессе нет.

## Статус
Первичный UX-аудит этапа 01 завершён по скриншотам с открытым backlog. **Текущий этап 02 — утверждение арт-дирекшна, hero-ассета и вариантов логотипа, не разработка.** Никакого интерфейса, кода, новой палитры или логотипа без утверждённых референсов и отдельного задания Codex.
