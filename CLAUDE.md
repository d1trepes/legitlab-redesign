# CLAUDE.md — главный вход для Claude Code

**LEGIT LAB / 08.11.2026.** Этот репозиторий — отдельная **концептуальная B2C-демоверсия**, не production. Репозиторий на момент передачи содержит брендовые ассеты и подробную документацию, **но ещё не содержит код сайта**.

## Задание в текущей сессии
Пользователь **явно разрешил разработку демоверсии в Claude Code**: не возвращай процесс к бесконечным аудитам и согласованиям. Прочти файлы ниже, построй работающий сайт, проверь результат и представь пользователю для визуального одобрения. Это **разрешение на реализацию обратимого прототипа**, не окончательное утверждение всей айдентики и не публикация в production.

**Сначала прочитай (в порядке приоритета):**
1. `CLAUDE.md` — действующие инструкции.
2. `docs/CLAUDE_BUILD_SPEC.md` — точное ТЗ сайта и сценариев.
3. `docs/ASSET_REGISTER.md` — реальные файлы, статус прав и правила использования.
4. `docs/REFERENCE_TO_SECTIONS.md` — композиция по секциям.
5. `docs/QUALITY_GATE.md` — условия завершения.
6. `docs/DECISIONS.md` — решения D-001—D-030; **новейшие решения имеют приоритет над историческими заметками**.
7. `docs/STAGE_02_ART_DIRECTION.md`, `docs/HERO_ASSET_MANIFEST.md`, `docs/PROPOSED_SITEMAP.md`, `docs/UX_AUDIT.md`, `docs/EXPERT_WORKFLOW_NOTES.md`.
8. Остальные `docs/` — углублённый контекст, а не блокирующие задачи.

## Неприкосновенное
- Бренд **Legit Lab**, адрес **legit-lab.com**. Только B2C, Беларусь прежде всего, русский UI.
- Стиль: **editorial fashion × streetwear × authentication**. Светлая монохромная тема — default, полноценная тёмная — через «Настройки». Выразительный крупный типографический ритм, реальный предметный арт, чистая плотная композиция, строгий UX.
- Главный знак **C2 Compact УЖЕ ВЫБРАН для дизайна**: `assets/logo/selected/C2-compact-selected.svg`. Не редизайни, не замени на иной знак, не добавляй LL-монограмму. Wordmark набирай текстом рядом, не объявляй его финально утверждённым.
- Пара исходных пользовательских hero-худи **УЖЕ ЕСТЬ**: `assets/hero/hero-hoodie-black-light.webp` (light), `assets/hero/hero-hoodie-white-dark.webp` (dark). Сохрани оригиналы. Не генерируй новые модели, руки, вещи, знаки и фотографии вместо них.
- Огромное декоративное **LEGIT LAB** с худи перед буквами; это НЕ H1. Семантический H1: «Проверка подлинности брендовых вещей». Описание: «Помогаем понять, стоит ли покупать вещь и что именно ты держишь в руках.» CTA: «Начать проверку», вторичный «Как это работает». H1, описание и CTA читаемы и ничем не перекрыты.
- Desktop framed navbar без hamburger: знак+wordmark, «Стоимость», «Кошелёк», «Статьи», Telegram, TikTok, «Войти», настройки, CTA. Если ссылки/продуктовые функции неизвестны, делай ясно обозначенные demo состояния, а не видимость работающего production.
- Секции **строго**: header → hero → «Примеры проверок» → «Как мы проверяем» → «Стоимость» → «Статьи» → финальный CTA → footer.
- На сайте CTA ведёт **к браузерному сценарию заявки**. Telegram bot/Mini App — отдельный путь, не принудительный redirect из веба.
- Запрещено выдавать выдуманные отзывы, числа пользователей, экспертные заключения, цены, сроки, сертификаты и легитимность платежей за факты. Конфиденциальные комментарии экспертов/клиентов не публиковать даже частично; не хранить в скрытом HTML.
- Не обещать 100% точность, гарантированный результат, 100%-ную оригинальность. Не подключать реальную оплату. Суммы BYN не выдумывать, при отсутствии проверенного официального символа писать **BYN**.
- Не копировать конкурентов пиксель-в-пиксель; нет бирюзы, неона, AI-glow, рандомных паттернов, мелкого технотекста, случайных «trust»-бейджей.
- Предпочтительные, но **не лицензированные в репозитории** шрифты: TT Firs Neue + TT Commons Pro. Не скачивай пиратские шрифты. Если лицензий/файлов нет, используй нейтральный системный fallback **только как временную техническую замену**, честно сообщи об этом. Не возвращай отклонённые Onest, Unbounded, Inter, Manrope в качестве брендового решения.
- Публичный релиз/реальная авторизация/платёж/правовые обещания — **не в этой задаче**.

## Как работать без лишних вопросов
1. Быстро инвентаризируй дерево и ассеты (всё, что нужно, уже документировано). Не проси заново референсы, логотип или два худи.
2. Создай проект **Next.js App Router + TypeScript**, CSS Modules или Tailwind — выбери один подход, объясни в README. Если на момент работы появилась другая кодовая база, сначала изучи её и не уничтожай без причины.
3. Реализуй **целую**, не обрезанную главную страницу на 1440 и 390 с обеими темами. Точный документ: `docs/CLAUDE_BUILD_SPEC.md`.
4. Создай функциональный демонстрационный путь `/check` на сайте: выбор категории/бренда, прикрепление фото (локально), просмотр шага/подтверждения и **явная маркировка, что данные никуда не отправлены**. Не обещай обработку или завершённую покупку.
5. Не оставляй мёртвые кнопки: внутренние переходы работают, внешние указывают на подтверждённые URL либо честно помечены как недоступные в демо.
6. Запусти установку, lint/typecheck/build, исправь ошибки, если среда позволяет. Сделай screenshots 1440/390 для двух тем, если есть браузерный инструмент; если нет — явно сообщи, что не проверял визуально.
7. Запиши принятые **временные** технические решения в README и `docs/IMPLEMENTATION_NOTES.md`; не переписывай историю прежних решений.
8. Покажи пользователю результат и список того, что требует его финального визуального выбора. **Не проси одобрение перед написанием каждого блока**.

## Конфликты и приоритет
Исторические документы могут содержать фразы «Codex не запускать до утверждения» — они относятся к предыдущему режиму. **D-030 разрешает Claude Code собрать изолированную demo-версию** из выбранных материалов. Это не отменяет правило: финальный внешний вид утверждает только владелец; production остается нетронутым.

Репозиторий приватный. Не добавляй ключи, токены, персональные данные, исходные комментарии пользователей или материалы без прав.
